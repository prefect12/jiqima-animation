# 微游戏快闪 — 风格提示词（v1）

> 每关只有两秒左右：整屏一个大胆配色，一句大字指令砸下来，底部倒计时条飞快缩短，动作一完成就盖一个大大的“成功！”或“失败！”。关与关之间越切越快、节拍越来越急。适合游戏预告、新手引导和“挑战类”社交短片。
> 样片：《五道指令》（15 秒）· `demo.mp4` · 源码 `demo.html` · 封面 `poster.jpg`

你要用 **微游戏快闪** 风格把一串小任务拍成连环闯关。用户给你一个主题，你拆成 4–6 个“一句话就能懂”的动作指令（两到三个字 + 感叹号），每个指令配一个一眼能看懂的小场景，关卡越往后越短、越快，中间故意安排一次失败，最后给一个结算画面。界面、角色、配色全部原创，不模仿任何现成游戏。

---

## 1. 这个风格是什么

它的快感来自“来不及想”：指令只停留零点几秒就缩到顶部，倒计时条一格一格消失，判定章一盖下就切下一关。每一关换一整套配色（背景色 + 斜条纹 + 主色），观众靠颜色就知道“换关了”。画面是扁平矢量：8px 深色描边、纯色块、硬投影大字，没有渐变。

## 2. 剧情：什么故事适合

| 本事 | 用法 |
|---|---|
| **一词指令** | “接住！”“躲开！”“按下！”——动词 + 感叹号，三个字以内。 |
| **越来越快** | 每关时长递减（2.6 → 1.6 秒），节拍递增（120 → 180 BPM），过场也越来越短。 |
| **一次失败** | 全胜会很平，第 4 关故意失败（萝卜叶断了），扣一颗心，最后一关再赢回来。 |
| **结算** | 五个 ✓ / ✗ 排一排 + 一个分数（4/5）+ “过关！”。 |

**结构（15 秒版）**：开场“准备 → 开始！”（0–1.0 秒）→ 第 1 关 接住！（1.0 秒起，2.6 秒，120 BPM）→ 过场 0.55 秒 → 第 2 关 躲开！（2.3 秒，135 BPM）→ 过场 0.5 → 第 3 关 按下！（2.0 秒，150 BPM）→ 过场 0.45 → 第 4 关 拔出！（1.8 秒，165 BPM，失败）→ 过场 0.4 → 第 5 关 吹灭！（1.6 秒，180 BPM）→ 13.2 秒起结算 → 14.45–15 秒淡出。每关内部：0–8% 指令砸入，20–32% 缩到顶部，12%–62% 倒计时，**62% 动作完成**，**66% 出判定**。

## 3. 视觉语言

- **每关配色**（背景 / 条纹 / 主色）：接住 `#FFD23F / #FFC000 / #3B1F8C`；躲开 `#23C9FF / #12B4EA / #FF2E88`；按下 `#FF3E7F / #F02468 / #FFF23A`；拔出 `#3DDC84 / #27C56E / #5A2D0C`；吹灭 `#6B2FD9 / #5A1FC4 / #FF9F1C`。描边和深色统一 `#15121E`。
- **斜条纹**：56px 宽、120px 间距、斜 −0.5 弧度，滚动速度 `160 + 关卡序号 × 90` 像素/秒——越往后条纹跑得越快。
- **节拍脉冲**：背景中心一个白色圆环，每拍从 200 放大到 500 并淡出（透明度 0.18）。
- **大字**：Noto Sans SC 900。先画一层硬投影（向右下偏移字号的 6% / 9%），再描字号 16% 的深色粗边，最后填色。指令砸入时 220px，缩到顶部后 100px、位于 y=92。数字和“4/5”用 Bungee。
- **HUD**：左上深色胶囊“第 N 关”（34px），右上三颗心（失去的那颗变成半透明白）；底部倒计时条 10 格（每格 72×32、圆角 12），剩 3 格时 12 Hz 闪白。
- **判定章**：半径 220 的圆，成功 `#3DDC84` 配白色 ✓，失败 `#FF3355` 配白色 ✗，16px 描边，倾斜 ±0.08 弧度；下面压一行 130px 的“成功！/失败！”；判定瞬间整屏闪白（持续关卡时长的 10%）。
- **过场**：深色底 + 反向斜条纹，上一关的颜色被一条斜线切走；中间 300px 的关卡号 + “/5”，下面“加速！”和 5 个箭头速度计（已达到的亮起）。

## 4. 动作语言

- 指令：`back` 缓动 0.08 关卡时长砸入（会过冲），同时整屏压一层 55% 的关卡底色让字更突出，然后 `easeOut` 缩到顶部。判定出现时指令缩没，免得和判定章撞车。
- 每关一个“动作曲线”：苹果 `easeIn` 自由落体、碗 `back` 滑到落点；铁球匀速横穿、小家伙正弦跳过；手指 `easeIn` 按下、按钮下沉 20px + 12 根放射线；拽萝卜时手抖（70 Hz 正弦 5px）、叶子断掉手 `easeOut` 飞走；吹蜡烛时火苗被吹歪、压扁，熄灭后三团烟上升。
- 镜头抖动：指令砸入和动作完成两个瞬间，0.2 秒、最大 10–14px。
- 结算：五个圆章依次 `back` 弹出（间隔 0.07 秒），“4/5”和“过关！”再依次砸下，80 片彩纸下落旋转。

## 5. 镜头语言

完全平面、正面、居中，没有透视。顶部一条是“指令区”，中间是“游戏区”，底部是“倒计时区”，三块永远不重叠——画面里的道具（手指、萝卜）要让开顶部指令，放到画面偏右。关与关之间用硬切 + 过场卡，不用淡入淡出。

## 6. 声音

- **芯片节拍**：每关按自己的 BPM 重新排：每拍底鼓、2/4 拍军鼓、八分踩镲、三角波低音 `[0, 12, 7, 12]`、方波旋律（小七和弦琶音 `[0, 3, 7, 10, 7, 3, 12, 10]` 高两个八度）。每关根音升两个半音（48 → 56），越往后越“紧”。
- **倒计时**：倒计时条走的那段，每拍一声高频 tick。
- **指令**：底鼓 + 四音方波和弦重音 + whip。
- **动作音**：苹果下落的下滑哨音 + 接住 thud/pop；铁球 whoosh + 起跳 jump；按钮 click + thud；拽萝卜的锯齿“使劲”音 + 叶子断 whip；吹蜡烛 whoosh + swish。
- **判定**：成功 = coin + 四音上行芯片号角；失败 = 蜂鸣器（98 Hz 锯齿 + 104 Hz 方波，0.5 秒）+ 三音下行“哇哇哇”。
- **过场**：方波上行扫频（200 → 1600 Hz）+ 每 0.05 秒一下、越来越响的军鼓滚奏。

## 7. 文字与标题

指令一律“两个字 + ！”；判定只有“成功！/失败！”；过场只有数字和“加速！”；结算“4/5 · 过关！”。所有字都要在 0.3 秒内读完。不要在画面上解释规则——画面本身就是规则。

## 8. 踩过的坑

- **苹果穿过指令横幅**：苹果从 y=−80 落下、x=760，正好从缩到顶部的“接住！”后面穿过。改成从 y=150 开始、x 移到 900。
- **判定章压住指令**：判定圆半径 250、中心 y=360，上沿盖住顶部指令，只露出半截字。判定时让指令缩没，圆缩到半径 220、上移到 y=320。
- **手指只出现最后 0.2 秒**：“按下！”的手指从屏幕外很高的地方落下，大部分时间看不见；改成一开始就露出指尖（y=170）。
- **手指和手挡住指令**：按钮和萝卜放在正中，从上面伸下来的手正好遮住顶部横幅，把这两关的道具整体右移 200px。
- **拔萝卜的手够不着叶子**：手的落点比叶子顶端高 70px，看起来像在空中比划。落点改到 y=330，让手真的攥住叶子。
- **封面选在闪白那一帧**：最初封面 8.3 秒正好是判定闪白，整张图发白。改成 5.45 秒（小家伙跳起、铁球冲来、倒计时剩两格）。

## 9. 制作流程（本仓库）

1. 改 `demo.html` 顶部的 `GAMES` 表（指令、时长、BPM、配色、输赢）和 `GAPS`，关卡起止时间自动累加；`HIT` / `JUDGE` 是每关内部的动作和判定位置。
2. 抽帧：`node _engine/render.cjs microgame stills 0.7,1.1,2.2,2.9,3.9,5.4,7.8,8.4,10.3,10.8,12.3,14.2`，拼 3×4 联系表逐关检查。
3. 出片：`node _engine/render.cjs microgame`。
4. 验收：时长 15.0，响度约 −17.2 LUFS。

## 10. 引擎用法

- `big(文字, x, y, 字号, 颜色, 缩放, 旋转, 字体)`：硬投影 + 粗描边大字，所有指令、判定、数字都用它。
- `stripes(颜色, 速度, 角度)`：滚动斜条纹；`hearts(剩几颗, 是否正在失去)`。
- 关卡定位：`GAMES.findIndex(g => t >= g.t0 && t < g.tEnd)`，关内进度 `u = (t − t0) / len`；找不到就是过场或片头 / 结算。
- 每关的小场景写在 `gi === 0…4` 分支里，只读 `u`，所以改时长不用改动画。
- `score()` 里 `GAMES.forEach` 按每关自己的 `bpm` 排鼓和旋律；`buzzer()`、`wahwah()`、`fanfare()`、`stab()`、`ups()` 是自建音效。
