# 产品界面演示 — 风格提示词（v1）

> 一个干净的浏览器窗口，鼠标像真人一样移动、点击、打字：写提示词 → 生成 → 挑一张 → 改一句 → 导出。界面是代码画的，所以每个状态都可控，不用录屏。
> 样片：《AI 海报工具演示》（15 秒）· `demo.mp4` · 源码 `demo.html` · 封面 `poster.jpg`

你要用 **产品界面演示** 风格演示一个工具的核心流程。用户给你一个产品（或功能），你把它压缩成 4–6 个操作，每个操作都有明确的“输入 → 反馈”。

---

## 1. 这个风格是什么

像产品发布会里的演示视频，但完全由代码生成：窗口、按钮、加载骨架屏、结果卡片、弹窗、toast 都是画出来的。好处是节奏可以精确到帧，失败状态、加载时间都能按需要安排；界面里的产品名写“示例产品”，不冒充真实品牌。

## 2. 剧情：什么故事适合

| 本事 | 用法 |
|---|---|
| **打字** | 提示词逐字出现，闪烁光标，每个字一个键盘声。 |
| **加载 → 结果** | 骨架屏扫光，结果一张张弹出。 |
| **挑选 + 放大** | 鼠标悬停卡片轻微放大，点击后放大到弹窗。 |
| **二次修改** | 在弹窗里再输入一句，结果当场变化（本片：换色调）。 |
| **导出 + toast** | 收尾动作，给观众“完成了”的感觉。 |

**结构（15 秒）**：输入提示词（0.7–2.5）→ 点生成 → 加载 → 四张依次弹出（4.4–5.3）→ 点开第二张 → 输入修改（7.5–8.6）→ 回车，海报渐变成新配色 → 导出 → toast → 关闭弹窗，卡片打勾。

## 3. 视觉语言

- **桌面背景**：`#E8ECF3 → #DCE3EE` 斜向渐变。
- **窗口**：白色圆角 18，大投影（blur 40、y 16、18% 黑）；标题栏 `#F4F6F9`，红黄绿三个点，居中地址栏（Roboto Mono）。
- **主色**：一个品牌色 `#FF6A3D`（按钮、选中态、输入框聚焦边框），按下时深一档 `#E0551F`。其他全部灰阶：正文 `#1D2430`、次要 `#6B7684`、边框 `#E1E6ED`。
- **字体**：苹方；按钮 600 18px，正文 14–17px。
- **卡片内容**：用渐变 + 简单图形代表“生成的图”，不要真实图片。
- **弹窗**：背景压暗 45%，卡片从原位置插值放大到中间。

## 4. 动作语言

- **鼠标**：关键帧列表 `[时间, x, y]`，段间 `ease` 插值；到位后停 0.2–0.5 秒再点。点击时指针缩到 85%，按钮下沉 2px，外扩一圈品牌色波纹。
- **打字**：均匀速度，约 9 字/秒；光标 1.5Hz 闪烁。
- **弹出**：`back` 缓动 0.35 秒，依次间隔 0.3 秒。
- **变色**：0.85 秒内两组颜色线性插值，同时一圈白框向外扩散。
- **toast**：从下方上浮 20px，停 1 秒后淡出。

## 5. 镜头语言

固定机位，窗口占画面 75%。需要强调时用“弹窗放大”代替镜头推近。结尾淡出到背景色。

## 6. 声音

- 轻快的钢琴和弦 + 四拍底鼓 + 贝斯，108 BPM，音量低。
- 每个字 `key`、每次点击 `click`、结果弹出 `blip`（音高依次升）、打开 / 关闭弹窗 `swish`、变色 `shimmer`、导出成功 `ding`。

## 7. 文字与标题

界面里的文字就是字幕：按钮文案、输入内容、toast 都要写成观众一眼能懂的中文。产品名写“示例产品”，地址用 `.example` 域名。

## 8. 踩过的坑

- 鼠标的点击坐标必须和被点的元素对上（第一版点开的是第二张，鼠标却停在第四张上）。
- 弹窗里的输入框和导出按钮要排在同一行、放在海报正下方，不要压到后面的卡片上。

## 9. 制作流程（本仓库）

1. 先在顶部定好时间常量（`TYPE1`、`GEN`、`REV`、`OPEN`……）和鼠标关键帧，再写画面。
2. 抽帧：`node _engine/render.cjs ui-walkthrough stills 1.5,5.6,8.4,10.9,12.9`
3. 出片：`node _engine/render.cjs ui-walkthrough`

## 10. 引擎用法

- `cursorKeys`：鼠标路径；`cur()` 返回当前位置。
- `poster(x, y, w, h, 序号)`：画一张结果卡片，`recolor()` 控制变色进度。
- `cardPos(i)`：四宫格位置。
